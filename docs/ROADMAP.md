# Delivery plan and verification

The goal remains a comprehensive Three.js terrain creation tool for stylized games, AA photorealistic games, and realistic simulations. The implementation is usable, but the full objective is still under development and has not passed a complete production-readiness audit.

## Resume checkpoint

**Terrain LOD preparation now reuses bounded grid interpolation tables.** Profiling the world traversal identified repeated triangle searches while preparing streamed terrain chunks. The builder caches up to eight dimension pairs, keeps each tile's height samples and returned arrays independent, and retains authoritative hole topology. Five exact legacy signatures plus varying-height, mutation, eviction and hole checks pass; all 338 unit tests, build and lint pass. Native world rendering passes in a fresh RTX browser after one run was interrupted by confirmed Windows Modern Standby. The isolated awake 32×32-chunk benchmark drops warmed median preparation from about 5.4 ms to 0.22 ms with exact output hashes. The final RTX 5060 traversal measures 18.86 FPS on battery, with 149.7 ms frame p95; steady 30 FPS still fails. This single traversal does not establish a controlled FPS gain over earlier unknown-power runs. Worker preparation, shader/upload scheduling and distant geometry remain priorities. See [evidence and limits](PERFORMANCE.md#terrain-lod-preparation-cache--20-october-2026).

**The foliage allocation/upload pass toward #9 is implemented.** LOD instance capacity now matches each level's existing deterministic density subset, unchanged packed plants retain matrices/IDs, and native current/previous streams use versioned updates with active-slot upload ranges. No density or visual settings changed. In the 50,000-plant CPU fixture, reserved authored instance attributes fall from 22.8 MB to 13.7 MB at 60%/20% LOD densities; this is not total scene memory. The bounded RTX 1080p fern comparison has identical final screenshots and overlapping frame times, so no FPS improvement is established. A spatial selection hierarchy prototype added overhead to the already-cached CPU path and was not retained. The pre-cache world traversal measured 17.92 FPS, 200.1 ms frame p95 and 69.3 ms CPU submission p95. #9 remains open for cluster/impostor representations and residency; full-density tree canopies still need those geometry reductions. See [measurements and limits](PERFORMANCE.md#foliage-allocation-and-uploads--20-october-2026).

**Foliage motion/history work for #7 is implemented on native WebGPU.** Wind and contact deformation now evaluate the previous drawn pose, match instance transforms by authored ID across LOD packing, and reject stale fresh/cross-fading cutout coverage. Current/previous data use two packed instance streams. Camera velocity uses frame-scoped, stable projection bindings; temporal rendering restores perspective aspect after jitter and resets camera/leaf history together after resize or explicit teleport invalidation. Build, lint, 329 unit tests and 15 targeted RTX Chrome scenarios pass. Fixtures include default WebGPU limits with tangents/vertex colors and 400 real CC0 ferns with shadows, water capture, LODs, pause, camera motion, teleport and resize. The 1080p fern comparison shows better reference agreement, overlapping GPU cost, and about 0.18 MiB more tracked GPU storage; this is not a dense-forest FPS result. [Behavior and limits](FOLIAGE.md#motion-and-temporal-stabilization) and [measurements](PERFORMANCE.md#foliage-motion-history--19-october-2026) distinguish this bounded improvement from the unproven dense-forest target. Next rendering priorities remain distant forest representations (#9), dense-scene spectral-ocean acceptance (#13), and whole-world frame pacing; spatial indirect lighting (#11) follows those budgets.

**web-ocean is now an optional native WebGPU ocean provider.** Select **Water → Ocean rendering → web-ocean · spectral** for six FFT cascades, wind/fetch, independent swell, choppiness, persistent whitecaps, seed and Balanced/High detail. Existing water optics, shoreline effects and local bodies remain integrated; ponds/lakes retain Standard waves. The adapted compute kernels run on the terrain renderer's device and share across synchronized world tiles. MIT credit and full upstream notices ship with editor/runtime builds. Build, lint, 325 unit tests and 13 targeted Chrome scenarios pass, including GPU failure/retry, shared/disposed resources, independent animation rates, coastal composition, undo and persistence. Full-scene performance and breaking surf remain unproven/pending; this is not a CryEngine-quality claim. See [controls and scope](WATER.md#choose-an-ocean-renderer).

## Current implementation

- Artist import workflows: prominent foliage/material entry points, multi-file/drop review dialogs, orbitable neutral-light previews, visible commit/cancel actions and keyboard focus recovery. Foliage packages local glTF dependencies, checks dimensions/complexity/credits, converts units/pivots and creates brushes or adds/replaces variants explicitly. Material source presets cover Blender, Unreal, Unity Built-in/URP, Unity HDRP and generic OpenGL/DirectX. Editable assignments convert ORM/RMA/MRA and Unity metallic/smoothness or mask maps into canonical ORM, choose normal conventions and show channel conversions before preview. Missing Unity PNG/TIFF/TGA alpha and overlapping output channels require correction. Engine packages, shader graphs, specular workflows and HDRP detail maps remain unsupported. Materials also support physical scale and per-map thumbnails/removal. All batch applications stage resources before one history step and support failure retry/cancellation. See [material import](MATERIALS.md#import-a-complete-texture-set) and [foliage import](FOLIAGE.md#import-plants-into-a-brush).

- Editor navigation: `V` starts a walk-placement preview; click anywhere on the terrain or press Enter to capture the mouse at that point. A ground footprint, eye-height/direction marker and screen label identify the exact starting point. Entry accepts steep slopes and does not reject points based on scenery, water or footprint clearance. Orbit/pan/zoom remain available while choosing; V/Esc cancels. Walking preserves the chosen yaw, starts level at the saved eye height (default 1.8 m), and uses WASD/mouse/Shift. `Shift+F` independently toggles fullscreen. Exit/focus loss restores the composed editor view. Editing is suspended during placement/capture. Movement stops at terrain edges/holes and has no jump/gravity, slope limit or continuous prop/foliage/water collision.
- Project scale: a Project tab exposes saved first-person eye height and resizing of existing terrain. Width/depth (8-10000 m) is independent of grid resolution and is also selectable before generation. Generation and the scene panel show physical size next to cell count; cell spacing is explicit. Resizing preserves sculpting, paint, holes and cell count, scales anchored XZ positions, and optionally scales elevation/water. Model dimensions, material rules and texture repeats stay in metres. Preparation precedes history changes; Undo restores the previous size. Camera distance and clipping limits adapt to large terrains.
- Sculpting: raise, lower, smooth, flatten, terrace, seeded noise, conservative thermal erosion brushes, seeded hydraulic channels and thermal settling with cancellable before/after previews, rotated add/subtract/set stamps, built-in and imported PNG alphas, fixed-time stroke sampling, and pen-pressure strength. Named portable sculpt presets preserve tool/brush/stamp/pressure settings, thermal brush slope, and precise custom alphas across projects; loading is undoable and rejects stale reads. Brush controls persist with the project. Live brush strokes preview an independent candidate; Escape/pointer cancellation and recoverable construction failures restore the committed terrain, foliage, props and picking. Successful release creates one undo step after collision preparation, while failed strokes preserve redo. Erosion retains the original scene through comparison, cancellation and settings changes; failed preview/application restores it and keeps the calculated result available for retry. Smooth or flat shading and 32–512 cell grids support different mesh budgets. Generation and PNG16/RAW16 import stage complete scene/collision replacements before history changes. Failures and cancellation preserve the current landscape, selection, test bodies and redo. Regeneration retains brush definitions, assets and authored settings; seed 0 is valid. Heightmap exchange preserves numeric precision and updates anchors/collision.
- Holes: a shared cell mask removes visible terrain and collision. Prop cutouts compose independently with painted holes and restore correctly when props are removed.
- Texture formats: material sets, individual slots and the ORM composer accept TIFF/TGA alongside PNG/JPEG/WebP. Imports allow 256 MiB source files while limiting decoded images to 16 megapixels and retaining the 384 MiB project asset budget. Native image headers are checked before thumbnails/decode; large converted maps can round-trip through native saves. Cancellable conversion embeds portable PNGs, normalizes orientation, preserves declared alpha and retains 16-bit TIFF numeric precision until final ORM packing. Unsupported layouts fail before history changes; see [supported layouts and limits](MATERIALS.md#tiff-and-tga-texture-formats).
- Surfaces: four PBR layers, altitude/slope rules, paint overrides, height blending, triplanar albedo/ORM/detail normals, normal strength and OpenGL/DirectX conventions, and 256²–2048² maps. Optional repetition reduction shares translated patch sampling across every map, preserves legacy rendering when disabled, and carries through presets and baked PBR exports without extra texture arrays. A preview composer packs separate numeric PNG/TIFF/TGA channels and browser-decoded JPEG/WebP into ORM, supports gloss inversion, and preserves 16-bit source precision until final 8-bit quantization. Portable surface presets carry maps, normal conventions, shading, and procedural fallback identity across projects and layer slots. Loading placement rules is optional; destination IDs, painted coverage, and foliage references remain intact. Surface controls, rules, paint clearing, maps, ORM and presets prepare independent data/resources before history changes. Cancellation and recoverable preparation/history failures preserve the current surface and redo. Shading-only edits retain spatial geometry; rule changes retain foliage, props and colliders.
- Foliage: mix up to 32 weighted models per brush with per-model scale/yaw ranges, alignment, wind, and crush response; import static GLBs; set allowed material weights and shared spacing; paint/erase and deterministically populate. Clear removes only the active brush’s plants with undo. Brush and population authoring preserve the committed document and draw state on recoverable generation, buffer-construction or history failures, including legacy instance-ID conversion. Portable brush files include referenced assets. Height ramps, vertex-color channels, and dedicated GLB scalar masks control per-vertex wind/contact response, with matching normals and lit/directional/point-shadow deformation. Rigid mesh parts remain fixed; masked contacts use sparse instance attributes. Spatial batches share model geometry and support frustum culling; pending GPU update ranges stay bounded while culled. Up to three per-model LOD assets, stable density thinning, a far cutoff, and hysteresis select each instance independently; hidden plants retain contact recovery. Timed dithered transitions preserve complementary coverage through reversals, density/far culling, and skipped levels; wind, contact, alpha cutouts, and directional/point shadows remain synchronized. Brush files include LOD-only assets, and static exports retain full primary populations.
- Props: direct mesh selection, move/yaw/uniform-scale handles, snapping, cancellable previews, one-step transform history, numeric controls, and transformed static collision. Placement, handle/numeric transforms, cutout edits and removal stage geometry/picking/collision before committing document data and history. Recoverable failure restores the original scene and mesh pose, selection and next ID, while preserving redo. Circular or rotated rectangular cutouts support local offsets and model-bounds fitting; holes match rendering and physics and survive JSON/GLB/runtime interchange.
- Environment: shared editor/runtime sun, procedural sky or embedded Radiance HDR/OpenEXR HDRI, exposure/tone mapping, fog, shadow quality, and lighting presets. Optional solar-time playback uses latitude/season/north orientation, an atmospheric sky, warm low-angle sunlight, moving shadows, night fill and matched fog. A 128-pixel cube probe and reusable PMREM buffers update indirect illumination at most twice a second; frame ticks leave authored data/history unchanged. The EXR path validates bounded single-part RGB/RGBA scanline panoramas, supports HALF/FLOAT input and normalizes scanline chunk order. Wind has matching lit/shadow deformation; optional tunable contact compression and frame-rate-independent recovery through an engine-independent spatial field.
- Photographic foliage: four editor default brushes using credited Poly Haven assets, with 15 self-contained GLBs totalling about 21.6 MB. Pine uses an approximate twig-photo canopy derivative with three detail levels; smaller plants use two variants each and simplified distance geometry. Startup failure falls back to procedural art; adding presets is cancellable, atomic and undoable. Core `createProject()` remains synchronous with procedural defaults.
- Runtime: typed core, Three.js, and optional Rapier package exports; standalone integration example at `/runtime.html`.
- Reference art workflow: an editable 96 m upland meadow with generated ground/grass color assets, four imported static meshes, 5,263 grass instances, 34 limestone props, four surface layers, authored lighting, LODs, wind, and contact recovery. Editor loading is cancellable and undoable; the runtime provides three viewpoints and an embedded native download. A deterministic builder, hashes, original PNGs, and exact generation prompts are included. See [the example guide](REFERENCE-SCENE.md).
- Asset lifecycle: project/model/brush/surface imports prepare before applying, expose cancellation, and discard stale work. Shared resources survive competing preparations; changed/removed models, failed candidates, texture arrays, and owned decoded bitmaps are released. Undo/redo prepares resources before moving history. The runtime exposes cancellation and one-shot preparation results. Terrain chunks, foliage batches, props, picking geometry and optional disabled colliders prepare before project replacement; recoverable construction failures preserve the current scene and history. Stale terrain/collision preparations are rejected before commit, and local terrain replacements commit all selected chunks together.
- Long-session editing: shared immutable history with 64 KiB terrain blocks, deduplicated embedded assets, ID-aware instance reuse, configurable step/CPU-memory budgets, independent mutable restores, and cancellable one-shot undo preparation. The editor reports step counts and estimated memory; distant steps expire while the nearest available state remains.
- Persistence/export: lossless native `.terrain` packages with binary buffers, shared embedded assets, bounds/checksum/schema validation, reusable encoder caches, and legacy JSON migration. Autosave and native file downloads encode immutable snapshots on a background worker. Pending autosaves coalesce, exact file requests preserve click-time state, live buffers stay attached, and unchanged referenced assets are reused across saves. Bounded queues and recoverable worker failures keep persistence from accumulating full document copies. IndexedDB stores immutable package Blobs in ordered, failure-safe writes. GLB presentation offers fast vertex colors or standard baked PBR atlases, retains instancing, props and water, with authoring state in a version-2 binary extension; version-1 inline extensions remain readable. Asset imports enforce a 384 MiB payload allowance. Undoable cleanup removes unused models while preserving all prop/brush/LOD references.
