# Native WebGPU rendering

The editor, asset import previews, `/runtime.html` and `/world.html` initialize Three.js `WebGPURenderer` asynchronously. The factory verifies the native backend and rejects an unavailable device instead of returning Three's WebGL fallback. Existing `.terrain`, JSON and editable GLB documents are unchanged.

Use current Chrome or Edge with hardware acceleration on localhost or HTTPS. The intended desktop device remains the RTX 5060; a browser's high-performance request is only a preference. Windows tests select this workstation's dedicated adapter through DXGI/Chromium. WebGPU can redact the model name to `nvidia blackwell`; the benchmark enables developer adapter information only in its temporary profile.

## Implementation and pass ownership

- `src/render/renderer.ts` owns native initialization, backend checks and serialized GPU validation scopes. Error scopes reject asynchronous GPU preparation failures before editor history/document commits. Scoped allocation checks also reject Three's placeholder fallback after a synchronous texture allocation failure, preserving the shared placeholder's ownership during cleanup. A lost device stops drawing and offers project saving; restarting the device requires a reload. Startup failure offers local-save download without creating a renderer.
- Terrain uses TSL node equivalents of triplanar array sampling, aligned stochastic tiling, four-layer height blending, DirectX/OpenGL detail normals, wet banks and shallow caustics. Native baking shares the same surface evaluation. Shared triplanar coordinates are evaluated before conditional sampling, including zero-coverage and anti-tiling branches. Compressed libraries still support eight shared map layers with four active terrain layers.
- Vegetation uses native instance attributes for wind, contact masks and complementary LOD fades. Position and analytic normal/tangent deformation are shared with native shadow passes through reusable shader functions. Material cache keys include node graphs, and repeated uniform references share one node binding. Leaf backlighting remains shadowed and respects authored thickness, tint and material selection.
- Native batch adapters are local to `render/native-foliage.ts`, `native-terrain-lod.ts` and `native-shadows.ts`. Foliage keeps authored `InstancedMesh` objects for picking/export and WebGL, while native draw proxies resolve geometry-owned instance attributes. Terrain LOD similarly uses one target attribute, retaining authored geometry and exact morph selection. Graphs are shared only across identical texture-array sets and shading modes; palette and shoreline values update per material. Opaque shadow alpha avoids the full surface graph. Per-source/light shadow overrides avoid repeatedly changing a global override; source/light/renderer disposal releases them. Source disposal defers override cleanup until the event finishes so Three does not release shared bindings twice. Scene transforms update once per composed frame and the host update flag is restored. These Three r186 adapters require review on upgrades.
- Dynamic atmosphere uses `SkyMesh` and double-buffered PMREM capture. Direct sunlight is excluded from the probe to avoid adding an unshadowed second sun. Three `CSMShadowNode` supplies three shadow cascades; camera/settings changes refresh their frusta. Native shadow layout changes replace the sun light identity to refresh Three's cached bindings, so hosts should read `environment.sun` when needed. The environment explicitly disposes child cascade shadow nodes as well as their lightweight lights.
- `webgpu-pipeline.ts` owns one scene pass with linear HDR color, packed view normals, indirect light and velocity attachments. Depth uses WebGPU's 0–1 convention. The opaque capture precedes water refraction/reflection. GTAO removes only captured indirect light. TRAA resolves history with reduced water history weight and optional RCAS sharpening. RenderPipeline owns the sole display/tone conversion.
- Resize, camera changes and history invalidation retire pass targets/history. Disposing the pipeline releases its targets, explicit intermediate textures and TRAA bootstrap depth texture. The bootstrap history target is initialized before binding setup so its first resize releases the initial upload. Stable capture bindings and MRT graphs prevent retained textures, shader programs and uniform buffers across rebuilds. AO and sharpening parameters update uniforms. AO without TRAA resolves multisampled depth to full-precision R32F for neighborhood gathers while retaining scene-color MSAA. Camera jitter, renderer target/MRT/clear state and temporary visibility changes are restored after use.
- Water preserves connected ocean/pond/lake placement, wave settings, detailed foam, depth absorption, refraction, approximate screen reflections and underwater attenuation. The optional [web-ocean spectral provider](WATER.md#choose-an-ocean-renderer) now uses the same native GPU device for six FFT cascades and persistent crest foam, with transactional switching and shared world-tile simulations. Explicit WebGL hosts retain Standard water only.
- Native lighting preparation exercises full-size shadow/screen resources in an isolated offscreen scene before document/history adoption. The editor shows cancellable preparation and composes rapid lighting edits against the latest requested values. A runtime host may render while its first environment load is pending. Three r186's geometry cleanup also finds shader-discovered attributes; `shared-geometry.ts` defers deletion of borrowed foliage buffers until their base geometry's final lease expires. This version-specific adapter is renderer-local.
- GPU readback for PBR baking is asynchronous. Standard GLB export retains base-color/ORM/normal images, including decompression of KTX2 model textures. Viewport PNG export copies a fresh display-converted frame into a mapped GPU readback buffer before presentation retires its canvas texture, then encodes CPU pixels. This avoids compositor-dependent canvas copies; row padding, BGRA channel order and opaque display alpha are handled explicitly. Preparation cancellation and failed candidates keep the live scene owned by its original document.
- Editor frame submission waits for the previous frame in both orbit and first-person modes, while input continues updating. The native migration regression holds queue completion and checks actual submissions as well as the next rendered camera pose; orbit draws must not accumulate ahead of startup/import preparation or walking.

The reusable runtime still accepts an explicit WebGLRenderer for existing applications and baseline comparisons. Its GLSL implementations remain alongside the node implementations. There is no editor backend selector or silent fallback. Custom host `onBeforeCompile` GLSL extensions need their own TSL equivalents on WebGPU.

Three is pinned to 0.186.1: older r180 generated invalid WGSL for array texture sampling with explicit gradients, which terrain needs. The current dependency includes that upstream fix. Type declarations use @types/three 0.186.0 and @webgpu/types 0.1.64. See the [official renderer guide](https://threejs.org/manual/pages/webgpurenderer) and [node post-processing guide](https://threejs.org/manual/pages/webgpu-postprocessing.html).

## Verification

Run `npm ci`, `npm run lint`, `npm test`, and `npm run build`. Then:

```sh
npm run test:browser -- tests/browser/webgpu.spec.mjs tests/browser/webgpu-world.spec.mjs
npm run test:browser -- tests/browser/foliage-batching.spec.mjs tests/browser/terrain-batching.spec.mjs tests/browser/foliage-crossfade.spec.mjs
npm run test:browser -- tests/browser/foliage-shading.spec.mjs -g "transmits backlight"
npm run test:browser -- tests/browser/foliage-recovery.spec.mjs tests/browser/surface-recovery.spec.mjs
npm run test:browser -- tests/browser/asset-import.spec.mjs tests/browser/settings-recovery.spec.mjs
```

Native tests assert backend identity and collect GPU validation errors, exercise terrain/foliage/sky/water composition, compare baked maps with the WebGL baseline, export GLB, resize/history reset, startup recovery, and stream the checked-in Meshopt/KTX2 forest/coast. Leaf probes separately measure sunlight transmission, shadow rejection and absorption. Editor integration covers imports, preparation failures, cancellation, undo/redo and autosave recovery.

Windows verification on 2026-10-19 used Chrome 155, Node 24.18.1 and the dedicated NVIDIA adapter (`nvidia blackwell` in the privacy-limited WebGPU report; the DXGI selector targets the RTX 5060 Laptop GPU). Build/type checks, ESLint and all 316 unit tests pass. Targeted browser checks pass for native composition and repeated resource lifetimes; prepared forest/coast streaming and shared-buffer unloading; foliage motion and leaf transmission; camera input under GPU pressure; device loss and unavailable-device recovery; daylight and HDR/EXR authoring; PBR/GLB round trips; water edits and failed allocations; and settings/history/autosave recovery. This is targeted migration coverage, not a full browser-suite rerun. The [native correctness record](benchmarks/webgpu-correctness-2026-10-19.json) contains bake differences and resource counts. The [forest screenshot](benchmarks/webgpu-forest-2026-10-19.png) and [water fixture screenshot](benchmarks/webgpu-water-2026-10-19.png) are correctness captures, not calibrated photorealism references.

Linux CI runs full Chromium under Xvfb with Mesa/Lavapipe for the Vulkan display and WebGL comparison path, and explicitly selects SwiftShader for native WebGPU. It records the adapter and permits bounded extra startup time for software shader compilation. Focused editor import/persistence checks start from a small real autosave; the full photoreal starter scene exceeded the software runner's three-minute startup limit. Dedicated-GPU checks cover default startup and full reference-world loading separately. This follows the software-driver approach in [Three's browser test harness](https://github.com/mrdoob/three.js/blob/dev/test/e2e/puppeteer.js). Timestamp queries are opt-in (`createTerrainRenderer({ timestamps: true })`); the world benchmark requests them explicitly. Software rendering is correctness evidence only. The two software texture filters differ by up to three 8-bit codes in the ordinary minified bake fixture; their comparison bounds are recorded separately from the tighter dedicated-GPU checks.

The [original sustained 1080p RTX comparison](PERFORMANCE.md#native-webgpu-migration-comparison--19-october-2026) measured 52.63 FPS for pre-port WebGL versus 0.147 for the first native implementation. Follow-up profiling traced the long freezes primarily to repeated TSL shader construction. The [optimized native run, before the final shadow-disposal correction,](PERFORMANCE.md#native-streaming-optimization--19-october-2026) now records **35.72 submitted FPS**, **54.8 ms p95**, and **1,200 ms worst interval**, with zero reported errors and zero tracked renderer/tile/asset allocations after teardown. A final-code retest measured 24.16 FPS with iRacing running; a clean retest remains pending. This is streaming/teleport responsiveness, not warmed stationary or editor FPS; steady 30 FPS still fails. The prepared reference world and rendering settings are unchanged, but the WebGL and native pipelines differ. Build, lint, 321 unit tests and targeted browser checks pass for this optimization; Linux/software and the full browser suite were not rerun. Dedicated vegetation motion vectors, distant forest representations and richer indirect lighting remain separate work. The optional spectral ocean is integrated, but its dense-forest performance budget is not yet measured. Screen-space reflections still miss offscreen scenery; the existing finite streamed-water boundary/connectivity limits remain. Safari/Metal, Firefox and Linux hardware drivers have not been validated in this Windows session.
