# Architecture and physics

## Data model

One versioned project owns a regular XZ grid with Y heights in metres, a cell-level hole mask, four paint channels per vertex, material definitions, foliage brush definitions, instances, props, asset data URLs, and environmental settings. Typed arrays hold heights, paint, and holes. Native packages retain their binary representations; the legacy JSON API uses numeric arrays.

Terrain is a heightfield, so it cannot represent overhangs or caves by itself. Holes remove complete cells. Separate imported meshes can supply cave interiors, entrances, tunnels, or buildings. A prop's circular or rectangular cutout is evaluated alongside the artist's hole mask without destructively changing it. Rectangles store local width, depth, and centre offsets, transformed by the prop's uniform scale and Y rotation. Model fitting snapshots projected mesh/node bounds into those local dimensions; it does not require model decoding in physics or represent a concave mesh silhouette. Cell-centre sampling produces the same mask for rendering, foliage visibility, erosion protection, and collision.

The grid diagonal is fixed. Surface sampling follows the same two triangles used for drawing and physics; this avoids the mismatch that bilinear height sampling introduces on nonplanar cells.

## Sculpting and elevation interchange

Continuous brush input uses a fixed-time sampler with pressure-scaled doses and spatial interpolation. Stamps apply once per gesture and use rotated alpha sampling; their update bounds include rotated corners. The first actual terrain hit creates the stroke transaction. Custom alphas and settings are serialized with the project.

Heightmap exchange uses normalized float data with bilinear grid resampling. A bounded PNG decoder preserves 16-bit samples through all five PNG filters without an 8-bit canvas conversion; RAW16 exposes byte order and dimensions. Imports build and validate a candidate height buffer before one undoable replacement. Terrain collision and placement anchors refresh from that same buffer.

Erosion uses an engine-independent generator with deterministic particle flow and conservative eight-neighbour thermal transport. The editor consumes it in a disposable worker, previews a separate height buffer, and commits only on Apply. Boundaries and vertices touching effective holes are protected. Soil carried out of the editable domain is accounted for as drainage; remaining loads deposit on evaporation or travel completion. Physics stays on committed geometry during preview, with test bodies cleared and editing controls locked. Original comparison, cancellation and settings changes restore retained scene/picking resources without rebuilding. Apply stages terrain/prop collision and history before publishing the candidate. Recoverable preview or application failures restore the committed landscape and preserve redo; the calculated result remains available for retry. Cancel terminates the worker without adding history.

## Rendering

The shared TerrainScene runtime builds 32-cell chunks from authoritative terrain buffers. Brush updates rebuild only intersecting chunks plus the normal/material-rule dependency halo, and the editor reuses their position buffers for picking. Adjacent chunks calculate normals from the same global height samples. Smooth shading and flat shading share topology; lower grid resolutions provide genuinely lower polygon counts.

Four material layers use altitude and slope rules, normalized weights, and painted overrides. Three.js MeshStandardMaterial supplies PBR lighting; shader extensions add triplanar albedo/ORM/height sampling, a height-aware blend, and detail normals. Imported maps are stored with the project. Texture arrays support 256²–2048² per layer, with a 512² default. Triplanar normal frames handle all axis signs and slope orientation. Each layer selects OpenGL or DirectX tangent-space normals; zero strength disables normal detail. A worker combines separate numeric PNG channels into ORM, preserving 16-bit source precision until final 8-bit packing, with preview and one-step application. Ambient occlusion affects indirect light rather than darkening the base color. Texture arrays are reused for parameter-only edits, and failed texture decodes do not replace the last valid project. Portable surface presets preserve maps and procedural fallback variants across layer slots while retaining the destination ID, paint, and foliage references. Loading placement rules is optional; the editor prepares images before one undoable replacement. Fallback variant changes invalidate texture arrays only where procedural maps are used. Optional `reduceTiling` blends three translated patches on a triangular grid with shared offsets/weights for all maps and explicit gradients for mip selection. The switch reuses arrays and leaves placement/collision unchanged; baked PBR uses the same sampling. Fourth-power weights reduce blend blur without a histogram preprocessing pass, at increased sampling cost.

Static mesh assets are instanced by brush, model entry, spatial tile, and mesh part. Each brush can hold 32 weighted model entries with independent scale/yaw ranges, alignment, wind flexibility, and crush response. Instances retain stable entry IDs; probability edits affect future placement. A shared spatial hash enforces minimum spacing across population tiles and repeated stamps within a brush. Brush authoring copies definitions and instance records, including legacy model-ID conversion, before generation or history capture. Visual changes prepare detached draw buffers before committing; future-placement metadata retains existing buffers. Per-brush clearing preserves other populations and definitions. Failed generation/preparation keeps the document, selection, instance IDs and history unchanged. Legacy single-model documents remain readable. Portable brush files embed referenced model assets and remap conflicting asset IDs on import. Wind bends foliage along a configurable horizontal direction with position-dependent phase and gust variation. The engine-independent FoliageInteraction field indexes instances spatially, stores sparse compression, and recovers exponentially in seconds. The preview feeds it actual Rapier ground contacts and applies changed transforms. Foliage is batched in 32 m tiles for frustum culling. Each instance selects its own distance LOD with hysteresis and a stable density rank. A tile caches the minimum distance to any next switching threshold, allowing exact skips when camera travel cannot change its selection; edited anchors invalidate that cache. Draw buffers pack only selected instances; authoritative transforms and contact recovery remain available while hidden. Up to three authored lower-detail meshes and an optional far cutoff are supported. Standard GLB exports reconstruct complete primary buffers independent of camera visibility. Lit, depth, and point-light shadow passes share the same wind deformation. Sparse contact changes look up affected tiles and packed draw slots directly by instance ID. All batches share the project’s wind uniforms. Height, vertex-color, and dedicated scalar bend masks control per-vertex deformation; sparse contact amounts are uploaded per instance. Lit and shadow passes share deformation and normal correction. Timed LOD transitions use complementary dither coverage, including density and far culling; static exports retain complete primary meshes. The contact field is CPU-based and engine-independent.

## Standard PBR export

Optional GLB baking evaluates the production surface shader in atlas UV space, producing sRGB base color, numeric ORM, and tangent-space normal PNGs. Shared surface uniforms prevent live and baked shading parameters from diverging. Exported chunks share one XZ atlas and explicit tangents; flat exports carry face normals. Only bake geometry fills holes, preventing blank pixels from filtering onto hole rims. GPU readback is asynchronous, render state is restored between passes, and temporary targets/materials/maps are owned and released on completion, cancellation, or failure. The editor holds document editing during export; runtime callers keep source resources stable until the promise settles. The editable project remains embedded at its source resolution. See [export limits](EXPORT.md).

## Authored lighting

Optional `EnvironmentSettings` stores sun/ambient parameters, sky colors or an embedded Radiance HDRI, fog, exposure/tone mapping, and shadow quality. `TerrainEnvironment` applies this consistently in the editor and standalone runtime without coupling terrain geometry to the host’s light rig. HDR preparation validates dimensions and complete scanlines before decode; staged textures are committed only after successful preparation. Three.js creates roughness-prefiltered environment maps from the linear half-float source and releases them when that source is disposed. Shadow fitting follows the terrain height bounds plus authored padding.

## Prop interaction

Viewport selection raycasts the actual prop meshes, including displaced model origins. An editor-only transform proxy previews the selected mesh, bounding box, and footprint outline without mutating the project. Horizontal movement preserves ground-relative elevation; Y changes elevation offset. Rotation is limited to yaw and all scale handles change uniform positive scale. Before committing a completed drag, the temporary mesh/proxy pose returns to the original so retained objects match committed data. Placement, completed drags, numeric prop transforms, footprint authoring and removal build an independent prop-record candidate. Terrain, foliage visibility, prop objects, picking and combined terrain/prop colliders prepare before history changes. A successful edit makes one history checkpoint; a recoverable failure restores retained resources, selection and instance IDs, preserving redo. Escape, pointer cancellation, focus loss, or another document action restores the preview without changing history. Cutout terrain/collision updates on release; the outline shows the proposed footprint during dragging.

## Physics recommendation

Use **Rapier as an optional adapter**, with shared terrain collision data as the toolkit's public boundary. This keeps authoring and rendering independent of the consuming game's physics engine.

Rapier supports both heightfield and triangle-mesh colliders. Heightfields are attractive for compact, regular terrain. Triangle meshes directly represent arbitrary missing triangles, so the first adapter uses the same chunk topology as the renderer. Terrain colliders rebuild after an editing stroke, rather than on every individual brush stamp. The preview uses a fixed 1/60-second step and CCD on dropped bodies. Terrain meshes enable Rapier’s internal-edge correction so contact normals from adjacent flat triangles do not give resting bodies unintended lateral velocity. Prop mesh flags remain unchanged.

The actual simulation tests verify that bodies rest on intact terrain and fall through holes. Ray tests verify elevation changes and prop-generated cutouts. The preview also builds transformed static prop colliders. Region updates retain distant terrain collider handles and skip visual material-weight work. Character/vehicle controllers remain separate integrations; they do not require coupling the core to Rapier.

For simulation use, solver settings, friction, timestep, scale, high-speed contacts, and target-hardware performance still require application-specific validation. A terrain toolkit should supply colliders and contact hooks, not claim universal simulation accuracy.

Sources: [Rapier colliders](https://rapier.rs/docs/user_guides/javascript/colliders/), [triangle-mesh edge flags](https://rapier.rs/javascript3d/enums/TriMeshFlags.html), [Rapier World API](https://rapier.rs/javascript3d/classes/World.html), [Three.js MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html), [Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html).

## Persistence and history

Undo retains an immutable graph of project data. Unchanged records, instance lists, and embedded strings are shared; Float32/Uint8 buffers reuse unchanged 64 KiB blocks. Instance IDs preserve sharing after deletion/reordering. A restore reconstructs independent mutable objects and buffers, so editing or inspecting a target cannot corrupt retained history. Reference counting releases blocks and interned payloads when the last retained state expires.

History defaults to 64 total undo/redo states and an estimated 256 MiB retained-data budget. The farthest reachable states expire first, preserving at least one state even when it exceeds the budget. The estimate includes buffer bytes, conservative string sizes, and graph metadata; it is not a process-heap or GPU limit. Live projects and temporary restore candidates are separate allocations. SDK hosts can configure both limits and read counts, estimated bytes, evictions, and oversize status from `history.stats`.

Autosave stores immutable native-package Blobs in IndexedDB, with ordered writes and failure-safe replacement of the last committed record. The reusable encoder caches unchanged asset blobs and releases removed payloads after the next successful encode. File downloads use the same package format. Legacy JSON autosaves migrate on the next successful save. Imports must be validated before replacing the current document. Validation covers dimensions, buffer lengths/ranges, normalized paint, nested metadata, unique identifiers, asset references, embedded-only payloads, environmental ranges, package bounds, and checksums. Asset imports check the shared 384 MiB payload allowance before committing. See [project files](PROJECT-FILES.md) for file limits and versioned layouts. Asset decoding finishes before an imported document replaces the open project. Undo and redo materialize a one-shot history candidate and prepare its scene resources before moving either stack. Commit checks the history revision and returns the exact candidate used by the renderer. Cancellation, decode failure, and stale preparations leave both stacks unchanged; callers dispose abandoned preparations.

Model and surface loaders separate preparation from application. One-shot preparation results own retained or newly decoded resources; abandoning them releases those resources. Model payload aliases share one decoded asset, while changed or removed assets release their last reference. The GLTF parser tracks dependencies, including texture clones and work that resolves after a failed root parse. Owned image bitmaps close on release; unique dependency URLs keep host Three.js cache entries independent. Surface arrays are staged per channel, with cancellation checks between allocations and image decodes.

Project, brush, model, and surface imports use a revision-checked editor preparation action with visible cancellation. New actions and edits cancel pending preparation. A failed or cancelled preparation keeps the document and history unchanged. Terrain chunks, foliage buffers, prop objects, and editor picking geometry now build during preparation. Optional physics prepares disabled terrain/prop colliders before history moves; simulation can continue on the existing colliders. Commit transfers completed resources and retires the old ones. Failed candidate construction releases partial allocations, including incomplete foliage batches. Local terrain rebuilds also replace all affected chunks together. The live brush path copies mutable project buffers and retains the original terrain, picking, foliage and prop state for the stroke. Preview chunks can be replaced repeatedly; obsolete preview buffers release while the originals remain owned. Collision candidates and a history checkpoint prepare at release, then one commit retires the original scene. Failure or cancellation restores references without a fresh geometry allocation. Autosave reads the committed project during a stroke. Hidden retained foliage keeps advancing animation/contact recovery. Erosion uses the same retained-state preview; original comparison and cancellation restore resources and shadow bounds, while successful application publishes heights/settings after collision and history preparation. Surface editing stages independent material records, shared-or-replacement texture arrays, uniforms, and (for placement rules or cleared paint) terrain/picking geometry. All resources validate before history capture; commit replaces surface fields on the existing project root so foliage and physics keep their current spatial state. Shading-only controls avoid terrain, picking, foliage, prop and collider rebuilds. Presets and ORM Apply share this commit path, including retry after failed history capture. Generation and heightmap import also use full-scene preparation before history capture, transferring the candidate only after scene/collider validation. Generation preserves reusable definitions and settings while replacing spatial buffers/instances; heightmap import replaces only heights. Pending file reads are revision-checked and cancellable. Previous simulation bodies clear only on a successful replacement. Other in-place editing paths still need whole-edit recovery; fatal browser/GPU failures and throwing host callbacks are outside these guarantees. See [runtime ownership](RUNTIME.md#prepare-cancel-and-replace-a-scene).

## Scope boundaries

The implementation includes a local editor, engine-independent core, and separately packaged Three.js runtime with type declarations. It is not a hosted service, collaboration platform, or licensed asset library. The original AGENTS.md remains unchanged as requested; current commands and module descriptions are maintained here and in README.md.
